# 4. How it works

[Documentation index](../README.md) · **English** · [Italiano](../it/04-come-funziona.md)

## The path of a key press

```
touch ──► TvDb.Remote.get(Key) ──► Btn.pattern(toggle) ──► ConsumerIrManager.transmit(carrier, pattern)
                                      │
                                      └── IrCodec: nec / necExt / nec42 / samsung / sony / rc5 / rc6, or raw
```

1. `MainActivity` maps every on-screen key to a `TvDb.Key` (`POWER`, `VOL_UP`, `OK`, `YOUTUBE`...).
2. The selected `TvDb.Remote` returns a `Btn`: either a **parsed** code
   (protocol + address + command) or a **raw** list of microsecond timings.
3. Parsed codes are turned into timings by `IrCodec`; raw codes are sent as they are.
4. `ConsumerIrManager.transmit(frequency, pattern)` drives the IR LED. The
   pattern alternates *mark* (LED blinking at the carrier) and *space* (off),
   in microseconds.

## Supported protocols

| Protocol | Carrier | Frame | Encoder |
|---|---|---|---|
| NEC | 38 kHz | 9 ms + 4.5 ms leader, 8-bit address, ~address, 8-bit command, ~command, LSB first | `IrCodec.nec` |
| NECext | 38 kHz | as NEC with a 16-bit address and 16-bit command | `IrCodec.necExt` |
| NEC42 / NEC42ext | 38 kHz | 13-bit (or 26-bit) address, 8-bit (or 16-bit) command | `IrCodec.nec42` |
| Samsung32 | 38 kHz | 4.5 ms + 4.5 ms leader, address repeated twice, command and inverse | `IrCodec.samsung` |
| Sony SIRC 12 / 15 / 20 | 40 kHz | 2.4 ms leader, pulse-width bits, sent 3 times 45 ms apart | `IrCodec.sony` |
| Philips RC5 / RC5X | 36 kHz | Manchester, 889 µs half-bit, toggle bit | `IrCodec.rc5` |
| Philips RC6 (mode 0) | 36 kHz | 2.666 ms leader, Manchester, double-width toggle bit | `IrCodec.rc6` |
| Raw | from the file | timings stored in the database | — |

NEC timing: a `0` is 560 µs mark + 560 µs space, a `1` is 560 µs mark +
1 690 µs space, with a final 560 µs stop mark.

**The toggle bit.** RC5 and RC6 TVs ignore a repeated frame unless a toggle bit
changes between separate presses. The app flips it on every new touch and
keeps it while a key is held, which is what a real Philips remote does.

### Example: the Hisense power code

`NECext`, address `0xBF00`, command `0xF20D`. Bytes sent LSB first:
`00`, `BF`, `0D`, `F2`. That is 15 ones and 17 zeros, so the frame lasts
9 + 4.5 + 32 × 1.12 + 15 × 1.13 + 0.56 ≈ **66.8 ms**.

## The database

`app/src/main/assets/tvdb.json` (about 495 KB) is generated by
`tools/gen-db.cjs` from the TV folder of
[Flipper-IRDB](https://github.com/Lucaslhm/Flipper-IRDB) (CC0):

- each `.ir` file is one remote; every button name is mapped to a `Key` with
  regular expressions (`vol_up`, `VOL+`, `volume_up` → `VOL_UP`, and so on);
- protocols the app cannot encode (for example Kaseikyo, used by many
  Panasonic remotes) are skipped, raw signals longer than 400 values are skipped;
- a remote needs at least 4 usable keys and power or volume;
- identical remotes are merged and the most complete one comes first;
- big brands (Samsung, LG, Sony, Hisense, TCL, Philips...) are listed first.

Format:

```json
{ "v": 1, "brands": [ { "n": "Hisense", "r": [ { "n": "Hisense EN3Y39H",
  "b": { "POWER": { "p": "NECext", "a": 48896, "c": 61965 },
         "YOUTUBE": { "r": [9000, 4500, 560, 560], "f": 38000 } } } ] } ] }
```

`p` protocol, `a` address, `c` command (little-endian bytes as integers),
`r` raw timings in µs, `f` carrier in Hz.

## The automatic search

`TvDb.powerSweep()` collects the power code of every remote and removes
duplicates by signature (protocol + address + command, or length and samples of
a raw code). The search sends them one by one; stopping it keeps the last brand
and model sent.

## Why the app is so small

No libraries: the UI is built in code with standard Android views, the
database is compressed JSON in the APK, the release build is shrunk with R8.
